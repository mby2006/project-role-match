01
检索与切分

带重叠的文档切分与分数阈值检索

对应岗位要求检索质量与上下文构造

项目做法

切分函数按 size 切片并保留 overlap，避免关键信息被切断；检索先扩大候选集，再按 min_score 过滤并截断到 top_k。

执行流程

chunk_document 先校验 size 和 overlap；从位置 0 开始截取 size 个字符并追加 Chunk；索引递增；到文本末尾就停止，否则把起点回退 overlap 继续切。retrieve 先对查询做 embedding，取 top_k*3 候选，过滤低于 min_score 的项，再截断到 top_k；answer 把命中块拼成带来源标记的上下文。

设计取舍

重叠切分保留跨块上下文，代价是索引体积和重复内容增加；先扩大候选再过滤提高召回，但增加一次打分和过滤开销。

适用边界

按字符数切分不保证句子或段落边界；min_score 和 top_k 未在真实语料上校准；示例没有处理多语言或超长文档。

面试追问与答题要点

Q1为什么切分要保留 overlap？

重叠让相邻块共享边界文本，避免关键句被切断后检索不到；代价是索引体积和重复内容增加。示例默认 400 字符切分、80 字符重叠，最终参数需要在真实文档上评测。

Q2为什么要先取 top_k * 3 再过滤？

直接取 top_k 再过滤可能因为低分项被剔除而导致结果不足；先扩大候选集，再按 min_score 过滤，最后截断到 top_k，能兼顾召回和延迟。

Q3min_score 设成 0.72 的依据是什么？

示例给了一个可运行的默认值，但源码没有记录校准过程。生产上应该用标注好的查询-文档对做召回/精确率权衡，而不是直接沿用示例值。

02
稳定性与重试

有界重试与指数退避

对应岗位要求第三方模型调用的容错

项目做法

模型调用只重试超时和传输错误，最多 3 次，间隔从 0.5 秒翻倍；最后一次失败继续抛出，其他 HTTP 错误直接暴露。

执行流程

_chat_with_retry 设置初始 delay；在 attempt 1 到 3 的循环中发起带 20 秒超时的 POST，并用 raise_for_status 抛出 HTTP 错误；只捕获超时和传输错误；未到最后一次时 sleep 后把 delay 翻倍；最后一次重新抛出。

设计取舍

只重试瞬时网络错误，避免对 4xx 等确定性错误做无意义重试；指数退避降低连续失败时的压力。代价是同步 sleep 会阻塞工作线程，且没有抖动。

适用边界

没有重试预算、熔断或幂等键；如果请求已被服务端处理，重试可能产生重复计费；示例没有故障注入测试。

面试讲法

可以讲第三方模型调用的重试边界、退避策略和哪些错误不该重试。

面试追问与答题要点

Q1为什么只重试超时和传输错误？

4xx 通常是请求本身有问题，重试不会改变结果；超时和连接错误更可能是瞬时故障。示例只捕获 TimeoutException 和 TransportError，让其他错误直接暴露。

Q2为什么重试间隔要翻倍？

指数退避可以避免连续失败时持续打满服务端。示例从 0.5 秒开始翻倍，但同步 sleep 会阻塞线程，且没有随机抖动，多个客户端可能同时重试。

Q3如何验证重试逻辑？

用故障注入让前两次请求超时、第三次成功，断言调用次数和最终结果；再断言第 3 次仍失败时会抛出。示例没有包含这类测试，属于待核实项。

03
评测与验证

离线检索与引用覆盖评测

对应岗位要求RAG 效果验证与回归

项目做法

eval_rag.py 用 hit_rate 检查检索结果是否命中期望来源，用 citation_coverage 检查回答是否覆盖期望引用，均返回比例。

执行流程

hit_rate 遍历用例，调用 retrieve，把结果转成 doc#index 集合，与 expected_sources 求交集并计数；citation_coverage 遍历回答和期望来源，检查期望集合是否为回答来源的子集；两者都返回命中比例。

设计取舍

基于来源集合的评测确定性强、成本低，适合回归；但它只验证有没有命中或引用，不评价回答事实正确性和表达质量。

适用边界

示例用例规模小，没有置信区间或统计显著性；citation_coverage 使用 zip，长度不一致时会静默截断；未接入线上日志。

面试讲法

可以讲如何用离线评测验证 RAG 检索和引用，而不是只看主观回答。

面试追问与答题要点

Q1hit_rate 衡量了什么，没有衡量什么？

它衡量检索结果是否至少命中一个期望来源，适合做回归；它不衡量排序质量、重复率或最终回答是否正确。需要配合 MRR、nDCG 或答案级评测。

Q2citation_coverage 为什么用子集判断？

它要求期望的每个来源都出现在回答的 sources 中，检查引用是否完整。但它只比较集合，不检查正文是否真的引用了来源，也不检查引用位置是否正确。

Q3如何让这个评测更适合回归？

固定用例和期望来源，加入版本化的基线、最小样本量和阈值；对长度不一致的 zip 增加显式校验；再把线上失败案例回流到用例集。
